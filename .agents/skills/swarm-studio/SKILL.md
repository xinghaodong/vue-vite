本知识库系统性沉淀了基于商业级无人机编队系统（SwarmStudio）的底层逆向分析成果、软件工程架构、离散计算几何数学模型以及飞控安全生命线标准。

## 一、 系统全景架构与工作流 (System Architecture)

无人机编队表演系统本质上是一个**空间时序离散点云编排与飞控安全交付平台**：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        1. 2D 创意点阵编辑器 (Pixi.js v8)                │
│   导入线稿/图片 ──> 步骤一:预处理/扣背景 ──> 步骤二:单像素骨架细化        │
│   ──> 步骤三:累积弧长等距布点 ──> 原色采样 (Color Applicator) ──> 构型树 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 导出 Scene 点阵与灯光数据 (JSON / SDF)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        2. 表演剧本时间轴系统 (Timeline Engine)          │
│   分镜1(图案A) ──[ 匈牙利二分图最优变轨求解 ]──> 分镜2(图案B) ──[变轨]    │
│   航迹防穿刺校验 (Deconfliction) ──> 空间安全间距网格约束 (>= 1.5m)    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 生成多帧 3D 轨迹时序流 (Trajectory Stream)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                 3. 3D 表演全景播放器 (Three.js WebGL + Bloom)          │
│   暗黑夜空 ──> 单 DrawCall 实例化 (InstancedMesh) 驱动数千发光无人机    │
│   GSAP 变轨平滑补间 ──> 虚幻霓虹泛光 (UnrealBloom) ──> SDF 工业协议交付 │
└────────────────────────────────────────────────────────────────────────┘
```

## 二、 核心 DDD 领域实体与状态模型 (Domain Entities)

遵循严谨的 DDD 领域驱动设计，严格分离**持久化业务模型 (State)** 与 **渲染视口缓存 (Projection)**：

1. **`Agent` (无人机物理实体)**：
   * `id`: 唯一编号（如 `uav_001`）
   * `x, y, z`: 物理三维绝对空间坐标（单位：米，通常 $Z=0$ 映射为 2D 正视图）
   * `color`: 机身 RGBW 高亮 LED 十六进制颜色代码（如 `#00f2fe`）
   * `size`: 视口标定粒子物理半径（默认 2.0 ~ 2.5 米）
   * `group`: 所属构型子队分组 ID
2. **`Motif` (几何构型图层基元)**：
   * 单个分镜中独立的几何图形组合（例如“文字图层”、“主体人物图层”、“装饰边框图层”）；
   * 支持独立的图层平移、旋转、缩放、图层显隐、图层锁定与独立点数配额分配。
3. **`Scene` (分镜剧本单元)**：
   * 编队表演的一个静态或稳态画面（包含所有无人机的坐标与颜色阵列）；
   * `duration`: 构型悬停观赏时长（秒）；
   * `transitionTime`: 切换到下一分镜的变轨过渡时长（秒）。
4. **`Cue` (时序动作提示点)**：
   * 时间轴上的关键动作事件（起飞 Takeoff、变轨 Morph、爆闪 Strobe、跑马灯 Wave、降落 Land）。
5. **`Show` (整场表演总工程)**：
   * 包含总编队无人机架数标定（如 400 / 800 / 1600 架）；
   * 空间硬约束（$D_{\min} \ge 1.5\text{m}$，最大上升速度 $V_z \le 4\text{m/s}$，最大水平速度 $V_{xy} \le 6\text{m/s}$）；
   * 包含按时序串联的 `Scene[]` 序列。
6. **`SDF` (Swarm Data Format 工业数据交换标准)**：
   * 跨软件与地面基站通信的标准 JSON 协议结构，包含网格起飞点标定、分镜关键帧、灯光时序帧。

## 三、 图像转构型核心算法数学模型 (Math & Geometry)

为解决图像布点“发粗、发糊、点位粘连成团、五官失真”的问题，必须采用严密的离散计算几何管线：

### 1. 图像二值化与背景抠除 (Stage 1)
* **灰度计算**：
  $$\text{Gray}(x, y) = 0.299 \cdot R + 0.587 \cdot G + 0.114 \cdot B$$
* **色度欧氏距离 (Chroma Distance)**：
  $$D_{\text{color}} = \sqrt{(R - R_{bg})^2 + (G - G_{bg})^2 + (B - B_{bg})^2}$$
  当 $D_{\text{color}} \le \text{tolerance}$ 时判定为背景透明化。

### 2. 拓扑单像素骨架细化 (Stage 2: Zhang-Suen Thinning)
粗糙轮廓会导致 2~4 像素宽度的带状粗点，必须通过形态学迭代将其剪枝为严格的 **1 像素单链拓扑中线**：
* 8-邻域排列：$P_2(\text{北}), P_3(\text{东北}), P_4(\text{东}), P_5(\text{东南}), P_6(\text{南}), P_7(\text{西南}), P_8(\text{西}), P_9(\text{西北})$；
* 剪除条件：
  1. $2 \le B(P_1) \le 6$（非零邻点数）；
  2. $A(P_1) = 1$（$0 \rightarrow 1$ 翻转次数）；
  3. 子迭代条件交替消除边界点。

### 3. 拓扑连续路径追踪与累积弧长等距重采样 (Stage 3: Arc-length Equidistant Sampling)
* **路径追踪**：将散落的前景像素按 8-邻域连通性连接成有序折线链集合 $\mathcal{C} = \{ C_1, C_2, \dots, C_m \}$；
* **累积弧长参数化**：对于每条曲线 $C_k = [p_0, p_1, \dots, p_n]$，计算各点累积弧长：
  $$s_0 = 0, \quad s_i = s_{i-1} + \|p_i - p_{i-1}\|_2$$
  总弧长 $L_{\text{total}} = \sum_{k} s_{n, k}$；
* **全局等步长下放**：根据目标无人机总架数 $N$，计算目标点距 $\Delta s = L_{\text{total}} / N$；
* 沿参数化样条精确线性插值定位：
  $$p(s) = p_j + \frac{s - s_j}{s_{j+1} - s_j} (p_{j+1} - p_j)$$
  **工程收益**：点位呈现严格均匀的“珍珠项链”排列，完全杜绝堆积糊斑，线条纤细极清！

### 4. 智能色彩采样 (Color Applicator)
* 将物理世界坐标 $(X, Y)$ 归一化并逆映射回原图像素坐标 $(u, v)$；
* 采样原图像素 $(R, G, B, A)$；
* **防死黑智能提亮**：对于白底黑线图（线稿），暗部线条如果照搬黑色，在暗黑夜空中将无法辨识。算法自动检测亮度 $L = 0.299R + 0.587G + 0.114B$：
  * 若 $L < 40$，自动提亮为冷白光或高饱和霓虹色；
  * 若为彩色区域，提升伽马对比度赋给机载 LED，保证夜空高保真还原原图色彩！

## 四、 空间防撞安全网格 (Spatial Hash Grid) 算法

无人机编队的核心生命线在于**绝对杜绝空中撞机**。工业标准要求编队中任意两架无人机的物理三维间距必须满足：
$$D_{ij} = \sqrt{(x_i - x_j)^2 + (y_i - y_j)^2 + (z_i - z_j)^2} \ge 1.5\text{m}$$

### 1. 空间哈希网格 ($O(N)$ 高性能检测)
传统的两两对比复杂度为 $O(N^2)$，当 $N = 2000$ 时每帧需要 400 万次距离计算，严重卡顿。
* 将空间以 $R = 1.5\text{m}$ 划分为立方体网格单元；
* 哈希桶键值：$\text{Key}(x, y) = \lfloor x / R \rfloor + \text{"\_"} + \lfloor y / R \rfloor$；
* 点位插入哈希表；查询时仅检索自身桶及相邻 9 宫格（2D）或 27 宫格（3D），计算量从 400 万次骤降至数千次，耗时 $< 1\text{ms}$！

### 2. 力导向物理斥力场平滑疏散 (Auto-Relaxation)
当检测到 $D_{ij} < 1.5\text{m}$ 时，施加虚拟胡克弹簧排斥力：
$$\vec{F}_{ij} = \frac{\vec{p}_i - \vec{p}_j}{\|\vec{p}_i - \vec{p}_j\|} \cdot (1.5 - D_{ij}) \cdot 0.5$$
经 15~20 次阻尼迭代迭代收敛，在最大化保留原本构型形状的前提下，一键平滑弹开重叠点位！

## 五、 匈牙利变轨最优匹配算法 (Hungarian Morphing Solver)

分镜 A 变换到分镜 B 时，如何为无人机分配目标点，使得**总航行里程最短且航迹互不交叉缠绕**？
* **数学抽象**：带权二分图最小全匹配问题 (Minimum Weight Bipartite Matching)；
* **成本矩阵**：$C_{ij} = \|\vec{P}_{A, i} - \vec{P}_{B, j}\|_2^2$（加入距离平方项可显著抑制长距离跨越）；
* **Kuhn-Munkres 算法**：通过引入顶标 $l(x)$ 与松弛量，在多项式时间 $O(N^3)$ 求解全局最优解，彻底解决变轨过程中的碰撞隐患。

## 六、 基于 REA (Reverse Engineer Anything) 的深入逆向操作指引

本项目在 `.agents/mcp_config.json` 中配置了 `rea` stdio MCP 驱动服务。当需要进一步分析商业系统的编译包时，可执行以下标准工作流：

### 1. 静态逆向解包与源码还原
```bash
# 解构提取前端 JavaScript Bundle 模块
npx -y rea-agents@latest recover-javascript-sources "C:/path/to/downloaded/assets" --output "./reverse-src"
```

### 2. 追踪特定关键符号与依赖图谱
```bash
# 静态追踪特定符号调用链 (例如 SpatialGrid 或匈牙利变轨求解器)
npx -y rea-agents@latest trace-javascript-semantics --entry "./reverse-src/main.js" --symbol "SpatialGrid"
```

### 3. 在线审查与网络探针
```bash
# 被动监测在线 CDP 页面目标
npx -y rea-agents@latest inspect-web-page --url "https://swarmstudio.x-itech.com/"
```
